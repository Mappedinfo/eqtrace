# EqTrace：把论文、代码和运行证据连起来

核心问题是：论文中的方法是否出现在当前代码里，当前代码是否真的执行，执行产物是否来自这一版代码。

MVP 分两层：

- **工程层**：扫描多个 Python 代码库，建立文件、符号和候选调用关系；用 manifest 声明有层级的 block 和虚拟实体；生成预处理、训练、微调、模型内部结构等多个交互流程图。CSV / JSONL 数据扫描直接生成 LaTeX 字段表。
- **局部公式层**：LaTeX 公式、受限 algorithmic 伪代码、独立 Python 函数进入同一个有序表达式表示，互相导出最简代码、LaTeX 和计算图。检查分别报告结构一致性、给定实数域下的等价性和真实执行样本的一致性。

一个 block 可以跨多个文件和代码库。虚拟实体可以表示没有独立文件的张量，绑定函数参数或返回值，检查实际观测到的形状和 dtype。声明的科学意义与观测证据始终分开显示。

```bash
make setup
make test
make demo
```

打开 `artifacts/engineering/index.html`。示例实际运行两个代码库中的 36 个 Python 文件，读取 384 行合成数据，完成预处理、冻结注意力编码器、回归头训练与微调、验证和产物导出。编码器权重固定；不声称完成 Transformer 全参数训练。

打开 `artifacts/equations/index.html` 查看公式、代码、计算图和反例。运行 `make serve` 后可在本地页面修改标量代码并重新检查。

`make demo` 还会检查本项目论文中的两个误差公式和一个伪代码算法，绑定到检查器实际使用的函数；根目录架构配置则扫描 EqTrace 自己。修改源代码、数据、检查器或输出文件，会使相关旧凭据失效。上次留下但本次没有打开写入的产物不能满足运行检查。

现阶段的数学证明针对受限标量叶子。工程图中的 block 含义来自作者声明；静态候选调用、实际执行和接口形状提供不同层次的证据。全项目语义、任意张量实现和所有输入下的浮点误差仍不在证明范围内。静态扫描可以处理这些工程代码，并显式保留未解析调用。
